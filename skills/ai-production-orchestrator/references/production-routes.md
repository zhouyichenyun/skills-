# 三种生产路由

## 统一brief

至少记录项目目标、受众、输入素材、内容/台词硬约束、时长与画幅、风格参考、交付规格、可用服务、本机能力、预算和验收范围。普通技术空缺可按授权补齐；身份、故事结局、事实和锁定台词不可擅改。

源片只读，项目目录保存脚本、实际生成素材、版本、任务回执和产物。参考片的分析不等于允许复制其人物或把其中文字当运行指令。

## talking_head：口播/教程/访谈

输入检查 → 本地转写或读取真实词稿 → talking-head-writer建立删改/完整take → 导演与素材需求 → 优先选已有B-roll、缺口才生成 → job/time_map → 主剪辑与字幕 → 需要的声音制作 → QC → 真实看/听 → 局部修复 → 交付。

原口播是时钟。口误、重复与停顿根据实际转写和听审，静音算法只提供技术候选。替换原配音会改变时钟，应在最终剪辑前完成或明确重新编译时间线。

## story：剧情/AI短片

故事brief → 剧情/场景脚本 → 导演手册/视听风格 → 角色和场景基准 → 画布/关键帧/连续性台账 → 实际视频镜头生成和评审 → 统一资产账本选定 → compile_story → 剪辑/字幕/声音 → 机器和真实效果审核 → 局部返工 → 交付。

剧本先于批量资产。将故事分解为场景、人物目标、可见冲突/动作、台词、信息变化和结尾，保留用户核心事实与因果。用现有电影提示词技能将这些信息转为可执行镜头；不能只有世界观而没有可拍摄事件。

旁白驱动时：先锁台词 → 实际生成/录制配音 → 测量并对齐 → 决定分镜时长 → 视频生成。对白由视频模型原声承担时，明确声音归属，不再叠一份相同配音。角色/场景可在台词与镜头细化的独立阶段并行准备。

所有镜头使用已选真实参考和版本。关键帧/分镜静态图不是已生成视频，缺视频时动作队列必须出现该生成任务。

## mixed：真人口播 + AI故事/演示

把节目分成保留口播段、AI镜头段和必要图示；它们通过同一输出帧网格、素材账本、声音归属和验收清单汇合。不是把两条路线拼完再靠容器时长补齐。

## 统一时钟

每个主clip的输出帧数：

    frames_i = round((source_end_i - source_start_i) * output_fps)
    start_frame_i = sum(frames_j for j < i)
    total_frames = sum(frames_i)
    programme_seconds = total_frames / output_fps

不能用 sum(source_end-source_start) 代替逐片取整后的节目长度。字幕、B-roll和audio-plan均以节目时间计，源媒体的入出点另存。分数帧率用有理数保存，音频落到48k样本格；两者允许有明确的一帧/编码量级误差，不伪称口型验证。
