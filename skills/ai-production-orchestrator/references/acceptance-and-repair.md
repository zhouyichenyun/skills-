# 审核、返工与交付验收

验收分四层，不互相替代：

1. 技术：文件存在/解码/帧数/时长/音轨/字幕时序/响度/峰值/输出规格；
2. 画面与内容：身份、场景空间、持物/动作/轴线、剧情因果、B-roll语义、AI畸形、字幕遮挡、肤色；
3. 听音：台词/专名/数字、口型与声音关系、接缝、配乐遮蔽、音效同步；
4. 软件：真正导入并重开/播放目标剪辑软件，核对重链接与原生效果。

用户只要求通用成片时，原生软件UI不是交付前置条件；仍明确它未验证。用户要求原生工程验收时，该项不可由XML可解析代替。

机器扫描0warning不是视觉/听音通过。音频脚本exit0也可能technical_review_required；QC exit10可能只是有意静帧/停顿的候选。适配器必须读取真实报告与coverage，不能只按退出码。

## 返工

给每个问题issue ID、节目区间、责任素材/阶段、证据、修复方式和复检要求。回到最早错误层：

- 主题/事实/剧情：脚本；
- 身份/空间/关键动作：选定参考或对应镜头生成；
- 长短/切口/B-roll：job/time_map；
- 字幕：对齐/词表；
- 发音/声音：对应cue或mix；
- 编码/响度：技术修复。

修新版本，invalidate责任节点及下游。已通过且无依赖关系的内容保留。自动技术返工最多2轮，候选生成也受总预算控制。达到上限仍失败则交具体缺口和已完成部分，不报告全通过。

## 交付

package_delivery只打包真实存在的文件：成片、SRT、需要的音轨/混音/时间线、资产引用、规格/哈希、审核和导出损失。保留本机重链接说明，不把云端路径写成用户电脑已有路径。

技术版本可标technical_done_pending_review。制作验收通过需要用户要求的检查有真实证据；not_checked、pending和仅声明intentional的缺证据事项不能自动变成accepted。

不发布到公开平台或把用户素材推到公开GitHub；交付仅在用户指定的范围内。
