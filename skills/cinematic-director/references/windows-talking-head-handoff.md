# Windows 口播、AI 素材与调色交接

这是当前仓库新增的集成附录，不属于上游原始文件。用于将导演方案交给自动剪辑、字幕与效果审核技能。沿用上游的调度、连续性与镜头设计；用户指定的内容、软件、交付规格和创作授权优先。

## 适用范围与执行边界

面向 Windows 上的剪映专业版 / CapCut 和 DaVinci Resolve。默认产出可检查的制作规格与交接数据，而非声称已经操作用户电脑。只有当前工具实际连接了目标软件，并且软件返回成功，才报告“已导入”“已剪辑”或“已调色”。

剪映草稿、FCPXML、EDL、OTIO、SRT 的支持由实际导出器和软件版本决定。导演技能只提供准确的素材、时序、层级和意图，不把普通 JSON 或 Markdown 称为可直接导入的工程文件。生成时间线后，由剪辑技能验证格式并说明已测试的软件或尚未实测的导入步骤。

## 口播优先的导演决策

先读取可用口播视频、时间对齐的转录或用户确认文案。没有转录时可先做画面方案，但不得编造台词和逐字时间戳。

- 以口播的事实、逻辑与自然停连为主干。删口误、重复和长静默时保留呼吸和完整语义；有意停顿、笑声、强调不机械删除。
- 每个视觉覆盖对应一句话、一个论点或一个操作。B-roll 负责具体证据、过程、细节或空间关系，避免仅由“科技感”“高级感”等抽象词驱动。
- B-roll 默认只覆盖画面；口播音轨持续。需要改成全屏插片、重录、补旁白或替换主讲画面时在方案中明确写出。
- 跳切遮挡先考虑已有 B-roll、相关细节、有效的画幅重构；不为每次删停顿添加转场。保留足够的人脸和眼神，让观众知道是谁在说话。
- 样片、AI 图像和生成视频分别标记；没有实际生成或检查过的素材只能写 planned，不能写 approved。
- 不把 AI 示意素材伪装成真实取证、真实产品功能或现场纪录。对应内容需保持“示意”的表达边界。

## 逐句素材覆盖与剪辑交接

每行使用稳定 ID。至少区分源素材时间、节目时间和字幕时间，不把三者混用。以实测帧率建立时间线，所有时间区间采用左闭右开；切点、帧数和音画偏移由剪辑脚本核算，导演不凭视觉猜小数时间。

建议交接以下字段；自动剪辑器已有 schema 时映射到它的真实字段，不假称此表可直接运行：

| 字段 | 内容 |
| --- | --- |
| dialogue_id / beat_id | 台词句或语义拍的稳定 ID |
| dialogue_text | 对齐转录或已确认文案；保留专名与数字 |
| aroll_media / source_in / source_out | 口播源文件与入出点；未知则留空并说明 |
| program_in / program_out | 保留内容在最终节目的区间 |
| picture_role | aroll / broll / insert / title / demonstration |
| picture_source / picture_status | 实际素材路径与 planned / generated / inspected / selected 状态 |
| coverage_reason | 覆盖哪句话、证明什么、遮挡哪次跳切 |
| video_track / audio_policy | 画面层级；例如 B-roll 在上层、口播原声连续 |
| edit_action / transition | 保留、删减、覆盖、变速或硬切；写明理由和必要余量 |
| subtitle_id / subtitle_note | 对应字幕区间及专名、断句、避让主体的要求 |
| generation_brief | 缺素材时的 AI 镜头任务；实际提示词由既有电影提示词技能展开 |
| continuity / grade_intent | 必须保持的视觉事实、匹配参考和调色目标 |

交接包可包含 director-book.md、coverage.csv、shot-list.csv、generation-briefs.md、caption-style.json、grade-intent.json；用户只要成片或一份工程时，按任务需要生成，不强制打印所有内部表。

Windows 文件路径使用实际绝对路径，明确盘符。准备可移交项目时使用统一 media 目录和相对路径映射；路径中有中文或空格时交给实际导出器正确转义。不要将云端 Linux 路径作为用户电脑上已存在的路径。

## AI 素材镜头指令

每项生成任务至少给出：关联台词 ID、可见事实、主体、场景、起始状态、主要动作、结束状态、景别、机位 / 轴线、一个主要运镜或固定机位、光源方向、色彩、时长与前后余量、画幅、禁用事实。

- 与主讲画面统一时间、光色和真实感；需要明显区分的解释动画或示意镜头应主动区分。
- 相邻镜头锁定主体、服装、道具、屏幕方向与动作状态。为后期覆盖准备可剪的起止余量。
- 需要可读界面、表格、数字或字幕时优先使用真实截图与后期图形；不让生成模型承担必须准确的文字。
- 不在素材中烧录最终字幕；交付干净画面便于剪映 / Resolve 后期排版。
- 已批准角色、场景或产品参考不得在生成提示词中重新设计。未实际检查的参考不标记为已核验。

## 字幕与画面安全区

SRT 管时间和文本，不携带通用的字体、描边或位置。字体、字号、换行、强调和安全区另交 caption-style.json 或明确的排版说明；具体软件效果由其字幕引擎实现。

默认中文字幕最多两行，按语义断句，数字、专名与一组词尽量不拆。字幕开始和结束对齐实际语音，不根据脚本文字长度伪造精确时间。口播压缩和删句后由剪辑器重映射字幕时间，并检查重叠、越界、零长与句尾截断。

没有平台模板时，可把左右各约 10%、上方约 8%、下方约 20% 作为竖屏口播的保守初始避让范围；这是可调整的制作默认值，不是所有平台的统一规范。字幕根据脸、手、产品、关键界面和平台 UI 再移动。横屏按交付要求另定，不直接套用竖屏坐标。

## 达芬奇调色意图

先确认素材的实际色彩空间、Gamma、白平衡与曝光问题；标签缺失时标 unknown 并检查图像，不能把普通 SDR / AI 素材当作 Log 再加一次转换。

分别交付技术校正与创意意图：

1. 技术：正确的输入解释 / 色彩管理、曝光与白平衡、镜间匹配、必要的降噪或去闪烁。降噪和细节处理以实际素材为依据。
2. 创意：匹配哪张已查看的参考、对比与饱和度方向、高光滚降、阴影色偏、主体与背景分离、统一的肤色与材质目标。
3. 交付：用户要求的 SDR / HDR、输出色彩空间、Gamma、峰值与显示检查。未指定时可建议常见 SDR 交付，但在不知道源解释和显示目标时不自动套转换。

口播默认肤色自然、不过度磨皮，不将所有肤色强制拉到同一个亮度数值；用肤色线、波形和参考画面对照做判断。AI B-roll 先匹配口播主镜，再加轻量统一风格，不逐镜随机套 LUT。LUT、DRX 或 Resolve 节点方案只有在实际创建、格式有效且执行器支持时才称为可用调色资产。

grade-intent.json 至少记录 shot_id、source_color_space、source_gamma、reference_id、technical_corrections、creative_look、skin_protection、output_target、verification_status。它是意图规格，不等于已经应用的 Resolve 工程或 LUT。

## 审核与纠错交接

把审核目标交给效果审核技能：语义完整、B-roll 对应台词、主讲与素材连续性、字幕准确与可读、肤色与镜间色差、音量和音画同步、输出规格。

每个问题定位到节目时间和镜头 ID，附可观察证据、最小改动、预计影响及复检方法。优先采取可逆的修剪、替换覆盖、字幕修正、音频或调色参数修正；涉及关键剧情、核心表述或重生成付费素材时遵守当前授权。修复后重新渲染或导出检查，不能仅因参数写入成功就报告“效果已通过”。
