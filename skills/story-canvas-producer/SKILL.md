# 角色、场景与故事画布制作

用户已明确：人物建模指影视角色设定、多视图定妆与一致性；画布自动选择可用方式。交付角色资产、场景资产、故事状态台账、候选对比与可视化分镜板。

默认使用本技能的离线画布执行器，真正输出可打开、可拖动和对比的 HTML 画布；不能只给文字后说“画布完成”。Canva 作为可选的可编辑页面交接，范围见 references/canvas-routing.md。

{baseDir} 是本文件目录。任务所需参考：

- [角色与场景资产](references/character-and-scene-assets.md)；
- [故事连续性与视频交接](references/continuity-and-handoff.md)；
- [抽卡、评审和局部返工](references/candidate-review.md)；
- [画布路由与数据契约](references/canvas-routing.md)。

## 1. 确定故事和已锁定事实

读取用户故事、人物关系、视觉参考和已经选定的素材。复用已确定的画幅、风格、角色与镜头，不要求重复填表。用户仅要求配置技能时不自行消耗额度生成角色或场景。

普通摄影和美术细节可按授权选择。核心身份、人物关系、故事结局或用户锁定造型不能擅改。用户明确保留某阶段批准权时遵守；其他可完成步骤连续执行，不把每一张图或普通技术选择变成例行确认。

建立稳定 ID：角色 CHAR_*、场景 SCENE_*、镜头 SHOT_*、素材 ASSET_*、候选 CAND_*。维护 board.json，素材计划与实际产物分开。只有文件真实存在且可查看，才可进入 generated/reviewed/selected 状态。

## 2. 角色定妆和多视图

先做角色设定：年龄段、面部辨识点、比例、发型、衣装层次、道具、可变状态和明确限制。用真实已查看参考建立身份锚点；生成一次好看的脸不等于完成跨镜一致性。

先生成有代表性的角色基准图，再以选定基准图作为实际参考制作需要的正面、侧面、背面、全身及表情/动作。只做本故事需要的视图，不机械生成全部角度。多格角色卡也要逐格检查是否还是同一个人。

调用可用图像生成工具真实制作；图像编辑遵守宿主要求使用相应图像编辑工具。编辑本地参考前先实际查看，传入准确的参考文件/近期图像，不把文本描述冒充传图。将工具返回的真实产物保存到任务素材目录并记录来源、参数、版本和使用目的。

## 3. 场景生成与空间合同

先固定时间、天气、光源方向、门窗、主要道具和可通行关系，建立场景空间合同。按镜头需要准备无人物场景基准、关键反打或道具细节；镜头改变不应让房门、窗户、桌面道具随机换位置。

角色、场景基准都已选定且真实可查看后，再做人物进入场景的关系图、动作关键帧与分镜。沿用选定参考，控制相对身高、接触关系、持物手、遮挡、机位和光线。不可用新生成图悄悄重新设计已锁定角色。

## 4. 故事过程连续

逐镜维护 before → action → after，包括人物位置、朝向、持物手、服装/损伤、道具归属、光色、时间和人物知情状态。下一镜从上一镜的状态出发；时间跳跃、交叉剪辑、回忆或刻意反差用 continuity_group 和有理由的 continuity_overrides 明示。

脚本只能核对显式状态键与引用，不能靠元数据证明画面一致。真实查看相邻镜头，检查脸、衣服、轴线、视线、道具与接触状态；按需要同时查看开始/结束画面。保持状态不等于每次复制同一构图，镜头语言仍服务剧情。

需要电影级提示词时读已安装 cinematic-video-prompt-engineer；导演方案读 cinematic-director。将选定真实参考、镜头起止状态、可见动作和时长交过去。只有用户任务要求视频制作时，才按授权调用视频生成服务；分镜图完成不能说成视频已完成。

## 5. 把“抽卡”变成有界筛选

默认每个目标每轮不超过 3 个候选、最多 2 轮；用户预算或明确要求优先。生成前列出不许变化的硬条件与本轮只改什么，避免同时乱改身份、场景、光线和构图导致无法判断原因。

每个候选独立 ID、真实图像、轮次和生成参数。实际看图后写 evidence、hard_failures 和评分，禁止只看文件名、提示词或模型成功状态就评审。身份、关键道具、空间关系或关键动作不成立先淘汰；审美分数不能抵消硬失败。

rank 只辅助比较已评审、证据完整、无硬失败的候选，不自动批准。按用户授权选择最符合故事的版本并写 selected；若用户要求亲自选，给真实对比图等待其选择。没达到硬条件的候选不能为了结束任务强行通过。

失败只返工受影响局部：重做侧脸、修手、换道具位置、补一个场景反打或重生成该镜，不把已通过资产全部推翻。达到轮次上限后说明剩余问题与最小调整建议，不无限生成或承诺必然出好图。

## 6. 在画布上管理和交接

执行器：

    python "{baseDir}/scripts/story_board.py" validate board.json --out output/board-check.json
    python "{baseDir}/scripts/story_board.py" rank board.json --out output/candidate-ranking.json
    python "{baseDir}/scripts/story_board.py" build board.json --out output/story-canvas.html

画布展示角色与场景资产、故事镜头、候选对比及连续性问题，支持拖动、缩放、过滤与评审导出。布局和备注导出为新文件，不直接覆盖 board。build 可以生成标为 invalid 的排障板，不能把它当验收通过。

PNG/JPEG/WEBP 可安全内嵌；超出资源上限时明确拆分章节，不偷偷丢图或把未显示的图当已检查。默认不依赖网络加载资源。

输出人物/场景设定、实际素材、board.json、连续性报告、候选评审、交接清单及 HTML 画布。素材路径是实际文件，计划素材保留 planned。交给自动剪辑时输出正确节目时序与真实视频/图像路径；静态分镜本身不是可直接剪辑的完整视频。

## 7. 效果审核

真实看图与视频，分别记录已检查、失败和未验证。用 video-review-autofix 检查最终视频技术问题，声音用 audio-production-director。检查最早出错层并局部修复后再看，不靠脚本 validate 的通过状态代替人物身份、故事可信度或画面审美。

交付说明实际生成了什么、选定了什么、为何淘汰、是否达到轮次上限和哪些效果仍待验证。用证据降低不合理结果，不声称任何生成模型都能无条件保障效果。
