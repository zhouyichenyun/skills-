# 口播结构与逐句稿

## 一页内容 brief

记录 `topic`、`audience`、`viewer_problem`、`promise`、`evidence`、`duration_target`、`format`、`tone`。区分用户锁定的事实和可自由调整的表现形式。受众描述要能指导解释深度，例如“刚开始用手机拍口播的独立创作者”，比“所有年轻人”更可执行。

内容承诺只保留一个主目标。列出开头承诺在哪里被兑现；没有兑现依据的收益用较窄、可证实的说法替代。

## 按任务选择结构

| 类型 | 推进方式 | 画面可承担的信息 |
| --- | --- | --- |
| 观点解释 | 问题 → 判断 → 机制 → 例子 → 边界 → 动作 | 对比、实际过程、简短图示 |
| 教程 | 结果 → 前提 → 步骤地图 → 关键操作 → 常见错误 → 最小行动 | 屏录、手部操作、前后对照 |
| 经历故事 | 具体处境 → 目标 → 阻碍 → 选择 → 后果 → 可迁移判断 | 当时资料、地点、可核实物件 |
| 产品演示 | 使用问题 → 操作 → 可观察结果 → 适用范围 | 产品实拍、界面、细节 |
| 问答 | 用户问题 → 直接答案 → 依据 → 例外 → 下一步 | 关键词、证据或真实演示 |

不把这张表当成固定段数或必须都有的标签。平静讲清问题也可以完成作品使命，不强加悬疑、夸张冲突或 CTA。

## 逐句工作表

| 字段 | 意义 |
| --- | --- |
| `line_id` | 稳定编号，修改仍保留可追踪关系 |
| `spoken_text` | 实际可说出口的句子 |
| `purpose` | 本句解决哪个理解问题 |
| `priority` | `essential` 或 `optional` |
| `evidence` | 用户材料、可核查来源或明确意见 |
| `performance` | 仅必要的停顿、强调或自然动作 |
| `visual_need` | A-roll、屏录、实拍、图示或无须额外画面 |
| `estimated_seconds` | 没录音时可估，必须写明 estimate |

先完整朗读，再调整长句。优先删除重复结论和无效开场，而非删除因果中间步骤。数字、专名和多层条件可留更多理解时间。已有原声任务若需要重写一句，明确列为重录句，不把重写文字假装成原音里已有的话。

## 准备下游

将重要句标给导演：需要看到什么、何时需要看见、观众为什么要看。导演可选机位、光线和动作，不能为画面效果改变原稿的事实。B-roll 段落标注功能，例如“展示按钮位置”，比“高级科技感”更可检索。
