# B-roll 检索、打分与 AI 素材简报

## 素材选择顺序

1. 用户提供、已授权且可读取的素材库。
2. 用户已购买或明确允许使用的素材来源。
3. 有明确许可、可取得证明的图库/素材站内容。
4. 缺口写 AI 生成简报，实际生成完成后才进入候选。

先理解需补哪类信息：实物证据、操作示范、概念解释、时空转换、情绪换气，或遮盖无法避免的跳切。优先让原始证据可见；不要用泛化 AI 画面伪装真实人物、事件或产品效果的记录。

## 可解释评分

先排除版权未知而不适合当前用途、不可读取、与事实冲突的候选。其余候选按 0–2 分记录：

| 项 | 2 分含义 |
| --- | --- |
| 语义相关 | 明确对应当前句的具体对象/过程 |
| 信息贡献 | 画面提供口播没有重复描述的信息 |
| 构图可用 | 对应画幅下主体与字幕安全区可用 |
| 时长/动作 | 可用动作完整、时长满足插入点 |
| 质量 | 分辨率、稳定性、曝光与压缩可用 |
| 连续性 | 光线、时代、环境和产品外观不冲突 |

总分用于比较候选，不是“客观电影质量分”。实际查看后附一句依据；没看过只能记录为待评估。相关性和真实性比装饰性高分更重要。

## asset-plan.json

顶层 `version:1`，`assets` 中每项记录：

- `id`、`line_ids`、`purpose`、`output_at`、`duration`。
- `status`：`ready`（用户/库素材已核对）、`missing`（缺素材）、`generated`（实际已生成并核对）、`stock`（实际已取得图库素材并核对）。
- `availability`：`ready` 或 `missing`，避免把来源类型误认为文件就绪。
- `source_type`：`user`、`library`、`stock`、`generated` 或 `undecided`。
- `source`：相对 job 文件的现有可读文件路径；缺素材时必须为 null。
- `source_url`、`source_start`、`candidate_scores`、`inspection_notes`。
- `rights`：`holder`、`license`、`proof`、`allowed_use`、`verified`。没有材料时写 unknown 和 false，不补造授权。
- `generation_brief`：只在需生成时使用；包含请求状态与简报，不能假称已生成。

进入 job 的条件：`availability=ready`，文件真实存在、可读取，许可适合用途并已记录。`status=missing` 的条目不能出现在 job.broll。

## AI 素材简报

读取已安装 `cinematic-video-prompt-engineer/SKILL.md` 的实际位置，按任务只加载必要参考库。简报包括：

- 对应句子及本镜需要帮助观众理解的信息。
- 目标时长、画幅、构图、运动起止与可用循环条件。
- 主体、场景、可见动作、光源、色彩与前后镜关系。
- 与口播 A-roll 不冲突的动作/方向；为字幕留出的区域。
- 必须保持的产品/品牌/人物事实；不能让生成器臆造的文字和细节。
- 生成模型已指定时自然适配；未指定时给通用提示词，不捏造模型参数。
- 提示词状态 `brief_only`、`requested`、`completed`、`reviewed`，各状态必须有实际依据。

常见简单知识口播可用静态示意图或用户屏录完成，不要默认每一处缺口都生视频。AI 生成画面本身不能作为现实事实的证据。
