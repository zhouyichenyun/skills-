# 配音、音效与配乐制作

一个技能调度三类音频生成，并把真实生成结果变成能用于剪辑的音频。生成依赖当前连接的服务；本地处理只需 Python 标准库、FFmpeg 和 FFprobe。

{baseDir} 是本文件目录。根据任务读取：

- 生成路由与准确参数：[references/generation-routing.md](references/generation-routing.md)。
- 不同剪辑需求的声音设计：[references/editing-profiles.md](references/editing-profiles.md)。
- 时间线、混音与软件交接：[references/timeline-and-mixing.md](references/timeline-and-mixing.md)。
- 执行前真实听审与修复：[references/audio-review.md](references/audio-review.md)。

## 1. 从剪辑需求建立声音方案

复用对话中已确定的主题、受众、语言、时长、画幅、情绪、素材和目标软件，不重复问技术参数。用户要直接生成时，选择适合的声线、配器、速度与混音起点后执行。只有缺失信息会改变核心台词、含义或用户硬约束时才补关键问题。

可读取口播编导稿、导演声音计划、job.json、最终剪辑、逐词稿或单个音频需求。新配音与原声关系要明确：

- 保留原声：原口播为 dialogue，其他声音围绕它安排；
- 替换原声：新 voiceover 替代对应原声，不把两份台词一起播放；
- 补充旁白：标明新增区间，避免无意重叠。

为需要的声音建立 audio-cues.json：稳定 cue ID、角色、对应镜头或句号、输出时间、用途、精确台词或生成简报、生成状态、真实路径及已测时长。没有时间线时可以先生成单项音频，再测量并交付；不要虚构精确同步时间。

用户仅要求安装或配置本技能时，不自行花额度生成样片。本次配置不等于指定了某个要制作的音频。后续任务明确要求生成音频或自动完成剪辑时，按该范围调用可用工具，不为已授权的普通制作加例行确认。

## 2. 分别生成配音、音效和音乐

先读 generation-routing.md，并重新核对当前实际工具 schema；工具描述中的新型号、搜索结果或账户列表不能覆盖可调用参数。

当前已连接 Runway，可通过各自的配音、音效、音乐入口制作：

- 配音传精确台词，中文设 zh。稳定解说与情绪对白走不同路由；语速先按可读性选，再以实际音频为准。不要把普通导演说明当成要朗读的台词。
- 音效描述声源、动作、材质、空间和起落；按动作时间点安排，环境声可显式循环。不要每个切口机械加 whoosh。
- 音乐描述叙事功能、情绪、配器、节拍和段落。口播默认无歌词、不过度抢中频；用户要歌曲时再写歌词。音乐入口没有精确时长参数，生成后必须测量并编排。

输入文件的上传仅在当前任务需要且已获授权时进行；纯文字生成不上传用户原片。生成失败、功能未开通或账户限制时保留缺口，不循环重试相同被拒功能，不伪造生成结果。

只有生成任务真正完成、文件可以读取，才标记 generated。返回任务 ID、写好简报或拿到失效 URL 均不能算完成。保留完整的原始下载 URL，在本地素材目录保存实际文件与来源；不把用户音频或私有链接提交公开仓库。

## 3. 测量并匹配剪辑

用 scripts/audio.py probe 实测文件时长、音轨与采样率。配音需要实际听审或可靠识别校对台词、专名、数字和结尾，不能凭文件元数据判定内容正确。

- 配音超出镜头：优先合理调整停连、重新生成，或在已有授权下调整文案/剪辑；锁定台词不能暗改。不得截掉词尾或把说话循环。
- 音效：将可听到的事件对齐真实动作，保留必要前导和衰减；不把文件起点误认为动作起点。
- 音乐：选择有音乐意义的入出点，匹配段落转折，必要时淡入淡出；仅在明确设计为循环且实际检查接缝后循环。

在 audio-plan.json 中使用最终输出秒数，不用删改前的源片时间。与 job.json 的逐片帧取整时长保持一致。只把存在的本地文件加入可执行计划；生成状态和创意简报另放 cues，不塞入不存在的 source。

## 4. 混音、分轨和成片

脚本接口：

    python "{baseDir}/scripts/audio.py" probe audio.mp3
    python "{baseDir}/scripts/audio.py" mix audio-plan.json --out-dir output/audio-v1
    python "{baseDir}/scripts/audio.py" mux picture.mp4 --audio output/audio-v1/mix.wav --out output/final-with-audio.mp4

先对齐、调节增益和淡化，再对选中的音乐/环境声做以人声为触发的 ducking，最后测量并统一主混音响度与峰值。默认 48kHz、双声道、24-bit WAV；常见网络交付以 -16 LUFS、-1.5 dBTP 为起点，用户交付规范优先。音乐不应掩盖关键台词，音效不应靠突兀峰值制造存在感。

输出包括 full-length 分轨、mix.wav、cue-sheet.csv 和 report.json。分轨保留各角色处理后的时间线；最终主混音另经过总线响度/峰值处理，不能承诺分轨求和与 master 逐样本一致。纯静音或不可测项目保留不可测状态，不冒称响度通过。

mux 只替换新副本的音轨，保留原视频流，不改变剪辑时长；不覆盖原片或已有输出。若混音与画面时长不符先修计划，不用盲目的 shortest 截掉内容。

## 5. 剪映、达芬奇与后续修改

剪映可导入独立 WAV / MP3 或已合成 MP4。分轨 WAV 从节目 0 秒开始，按完整节目长度排列；在时间线起点对齐即可，不要同时播放原口播和已含口播的主混音。SRT 仍由字幕流程单独管理。

达芬奇 / Premiere 的已有 FCP7 XML 可通过本技能的 audio_nle.py 写入分轨或主混音：

    python "{baseDir}/scripts/audio_nle.py" --timeline picture.xml --audio-dir output/audio-v1 --out output/with-sound.xml --mode stems

该命令替换新 XML 副本的原音轨，保留视频轨，避免双重口播。stems 适合继续混音；mix 适合保持最终主混音。结构导出不是已在本机软件导入，Windows 软件版本和实际 UI 仍要验证。剪映原生草稿仍沿用已有同版本模板适配边界，不将 XML 称为剪映原生工程。

## 6. 审核、修复和交付

先读 audio-review.md。调用 video-review-autofix 检查最终成片的解码、结构与响度；配音准确、音乐遮蔽、音效材质、循环接缝和情绪贴合需要实际听审，未听审不能标为通过。

对问题定位到 cue ID 和输出时间：发音错误重生成对应语句，音效不匹配替换该 cue，音乐遮蔽调整增益/ducking，时序错误修计划，技术问题修新副本并重检。保留原文件和上一通过版本，最多两轮自动修复；不为局部错误重做全部素材。

交付真实生成的配音/音效/音乐、全长分轨、混音、计划与审核记录；按用户需要附合成视频和音轨 XML。说明实际生成、仅规划、技术已测与听审状态，不用任务提交成功替代声音效果通过。
